# 项目主源规则（Project Rules）

> 单一主源：所有会话/平台先读本文件与 `_记忆索引.md`。
> 分层：`LAYER:UNIVERSAL` 通用翻译规则（可投喂外部 AI）；`LAYER:LOCAL` 本地工程层（路径/省 token，投喂前剥离）。
> 术语定译权威 = `glossary.md`；任务 = `TODO.md`；决策史 = `implementation.md`。

<!-- LAYER:UNIVERSAL_START -->

## 一、通用红线（违反即事故）

1. **中文原文零改动**（含标点与空格）。原文文件有 MD5 基线（`项目文档/原文MD5基线.json`），可查证。
2. **对照版是唯一真源**：所有修改落 `第X章初译_对照.md`；`第X章译文.md` 为脚本派生物（`tools/sync_bilingual.py` 生成），禁手工编辑。
3. **对照版中文行与原文逐字一致（含全角标点）**；半角标点用 `tools/normalize_cn_punct.py` 归一并 `tools/scan_halfwidth_zh.py` 复核为 0。
4. **术语一个词条一个定译**（禁 `A / B` 并列）；定译终裁权在用户，AI 只标 `[!]待裁定` 不擅改；变更须回溯已产出章节。
5. **术语表仅供参考**：与更地道译法冲突时以地道表达优先并标注待更新（MTPE 元规则）。
6. **禁止凭记忆断言一致性**：结论带章号+行号，脚本复跑验证。

## 二、翻译与审校规则

- 优先级：**忠实原文 > 术语锁 > 跨章一致 > 表达自然**。
- 去 AI 痕迹写作时自检（humanize 类目）：AI 高频词、`VERB+-ly` 弱填充副词、em dash 滥用、三段式排比等，落笔即改，不留审校兜底。
- 英文润色：**禁用 -ly 副词修饰动词**（换强动词或重组句式）；专名/官衔高频重复属忠实必要，不强行换代词。
- 句长门禁：复合句 ≥40 词且连接词 ≥3 → P0 必拆；无从句堆叠的长句不误伤。段长 ≤150 词。
- 审校分级：P0 致命（漏译/误译/红线）/ P1 严重（术语错）/ P2 流畅 / P3 润色。
- **反向护栏**：不把正确但陌生的表达判错；不为改而改；外部意见不破坏已锁定术语/人名/诗词方案。
- **外部审校甄别**：先逐字核对引用与磁盘（引用失真率高发）→ 一致+属实落地 / 一致+不实反向护栏 / 失真+属实按实际行修 / 失真+现文已更优跳过。
- **五类致命缺陷优先扫**：代词指代对现场 / 施受关系还原中文主语 / 母题数字·道具专名禁换词 / 红线专名禁简写 / 动词按世界观质感。

## 三、诗词与专名

- 诗词有权威译本必引用并标 `[TN: Translated by …]`；自译必标 `[TN: Translator's rendering]`。
- `[POEM]/[PUZZLE]` 标记内容遇标记即停机交人工，禁止自动硬翻。

## 四、本地工程约定

- **五件套必须留根**：`README.md` / `_记忆索引.md` / `TODO.md` / `implementation.md` / `glossary.md`（移走 = 大量引用失效）。
- **原文就绪**：第1-90 章在 `章节原文/第X章/`；第91-351 章原文在 `章节原文/00_原文库/`（只读，不入 git）。章内 `归档/` 可能存早期成品，判"缺"前先查。
- **工具**：`tools/` 脚本一律 dry-run 默认、路径由 `__file__` 推导；中文路径勿直传 PowerShell（GBK 乱码），用全 ASCII glob 定位。
- **省 Token**：待读清单一次并行读；不重复读；`@` 引用优先。
- **git**：commit 用英文单行；只提交部分改动用 `git add <明确路径>`；大批删除/结构变更前先确认。
- 编辑节奏：`replace_in_file` 同文件每批 ≤3 次；操作前先 read_file（防 IDE 空壳）。
