# 联网核查（web-verify）

> 原则：**内知负责"提出假设"，联网负责"给出证据"**。查不到就写"未获证实"，不臆造、不用旧印象充数。

## 何时必须联网（触发清单）

| 类别 | 典型情形 | 最少来源 |
|---|---|---|
| A 敏感 | 政治体制/机构名/现当代人物、领土与地名争议、宗教与民族表述 | 2 源，含 ≥1 官方或权威媒体 |
| B 真实性 | 历史人物、朝代官制与封号、典故出处、引文、统计数据、作品/作者信息 | 2 源 |
| C 时效性 | 近 3 年网络流行语与新词、平台政策、版权授权、货币与度量、发布规则 | 2 源，优先近 12 个月 |
| D 平台规范 | {{平台}}（如起点国际/Webnovel/Dreame 等）的投稿规范、分级、敏感词 | 官方页面优先（web_fetch） |
| E 资料检索 | 论文、文献、参考资料 | 出版方/学术库/DOI，记录完整引用 |

**兜底规则**：不属于上表，但内知置信度不是"高"的 → 仍应核查。

## 六步 SOP

1. **内知先判**：写下"我记得是 X（置信度 高/中/低）"，作为待验假设。
2. **判定是否命中触发清单** → 命中则**强制** `web_search`；未命中但置信度非高 → 建议核查。
3. **检索**：中英双语关键词各跑一次；≥2 个**相互独立**的来源；官方/原始页面用 `web_fetch` 直取。
4. **交叉验证**：一致 → 采纳；冲突 → 并列记录并标 `[待人工裁定]`；**禁止用"我认为"压过来源**。
5. **落记录**：按 `references/核查记录模板.md` 追加到 `{{核查记录文件}}`（默认 `项目文档/联网核查记录_YYYYMMDD.md`）。
6. **回报**：只给"结论 + 来源（含 URL 与抓取日期）+ 对译文的影响"，**不据此直接改译文或术语**。

## 红线

- **终裁权在用户**：核查结果一律是 `[建议]`，改不改由用户裁定（与 glossary 术语裁定规则一致）。
- **不确定就是不确定**：搜不到 → 写"未获证实"，并列出已试检索词。
- **敏感内容只查事实**：不做规避性改写建议，除非用户明确要求。
- **既有红线照旧**：中文原文零改动、对照版唯一真源、译文为派生（`tools/sync_bilingual.py`）——核查不得成为改原文的理由。
- **引用可追溯**：每条结论带 URL + 抓取日期；付费墙/失效来源须注明。

## 本项目适配（第二本小说）

- 高频场景：古装官制/封号/器物（B）、异域保留分级（见 `.codebuddy/rules/novel_rules.md`）、海外发布平台分级（D）。
- 与术语流程衔接：核查结论若影响定译 → 记入 `glossary.md` 的 `[建议]` 项并附来源，**不直接改权威主表**。
- 批量核查前先列"待查清单"，一次性并行搜索，避免逐条来回。
