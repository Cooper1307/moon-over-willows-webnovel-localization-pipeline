# prompt 澄清与结构化（prompt-sharpener）

> 目的：把"口语化、松散的需求"变成"AI 能一次做对的结构化任务"。**只重构表述，不改意图。**

## 触发条件（命中任一即启用）

- 一条消息塞了多个任务，未编号、未分优先级
- 指代不明：「那个文件」「上次说的」「按老规矩」（前提不在本会话）
- 缺少三要素之一：目标文件 / 范围 / 交付物
- 长口语描述，关键约束散落在长文里
- 涉及不可逆操作（删除/覆盖/大批移动）但边界不清
- 用户说"直接做"，但验收标准未知

## 流程

1. **判度（关键）**：低含糊 → **不打断**，按最合理假设执行，回复首行标注「假设：…，不对请纠正」。
2. 高含糊 → 走步骤 2：直接重写为任务卡片回读；若存在影响方向的歧义 → 先给 ≤3 个澄清问题。
3. 用户确认卡片 → 按卡片执行 → 交付时对照卡片逐项勾销。

## 任务卡片模板

```markdown
【目标】…
【背景】…（一行；尽量引用用户原话）
【输入】…（文件 @ 或待读清单）
【范围与边界】做…；不做…
【约束/红线】…（原样保留用户约束字眼，不升级不稀释）
【步骤】1. … 2. …（含验证点）
【交付物】…（文件路径 或 回复格式）
【验收】…（怎样算完成）
【待澄清】…（≤3 条；若无则删除）
```

## 澄清问题的写法

- 给选项/例子（"指 A 还是 B？"），方便一键回答
- 一次最多 3 个，只问影响执行方向的问题
- 不重复已能从上下文推断的细节

## 红线

- **歧义不靠猜**：涉及原文改动/术语裁定/删除覆盖等不可逆动作，必须先确认。
- **不升级用户意图**：用户说"试试"不能变成"保证"；说"大概"不能变成"确定"。
- 已 `@` 的文件以磁盘内容为准；重写 prompt 不改变任何文件内容。
- 本 skill 只负责"把需求说清楚"，不代行翻译/审校/联网核查等执行逻辑（那些见 `translation_sop` / `web-verify`）。
